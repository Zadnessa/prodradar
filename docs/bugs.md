# Антипаттерны и типичные ошибки

Справочник ошибок, которые уже были допущены в проекте. Перед внесением изменений прочитай соответствующую категорию. Не повторяй эти ошибки.

## Нормализация данных

### Grade без нормализации регистра и разделителей (BUG-018)
Значения `grade` из API приходят в нижнем регистре и с запятой как разделителем (`middle, senior`). Без нормализации фильтры не матчат, а данные теряют консистентность. Все значения `grade` обязаны проходить через `normalize_grade`: Title Case, запятая заменяется дефисом, `Lead`/`Head`/`CPO` маппятся в `Lead+`.

### work_format без нормализации (BUG-019)
Сырые значения из API (`На месте работодателя`, `Полный день`, `remote` и т.д.) не совпадают между источниками и ломают фильтрацию. Значения маппятся в четыре стандартных варианта: `Офис`, `Удалёнка`, `Гибрид`, `Не указан`.

### Lead+ теряет плюс при нормализации (BUG-026)
Символ `+` в `Lead+` несёт смысловую нагрузку — это отдельный грейд, не вариант Lead. Операции `strip` и `replace` не должны удалять `+` из значений грейда.

### Обрезка description (BUG-051)
AI-фазе нужен полный текст описания для анализа. Лимит длины `[:500]` в парсерах удалён — в поле `description` сохраняется полный текст без усечения.

### Нет обратного маппинга grade в experience (BUG-053)
Источники вроде VK и T-Bank отдают только `grade`, оставляя `experience` пустым. Если `grade` заполнен, а `experience` равен `не указан` — `experience` выводится через `experience_from_grade()`.

### City «Не указан» при work_format «Удалёнка» (BUG-054)
Для полностью удалённых вакансий отсутствие города не несёт смысла и ухудшает фильтрацию. Если город пуст, а `work_format` содержит `Удалёнка` — подставляется `city="Удалёнка"`.

### normalize_grade не обрабатывает пару грейдов через пробел (BUG-074)
T-Bank может вернуть несколько грейд-тегов, которые парсер склеивает через пробел (`Lead Head`). Строки вида `«Grade1 Grade2»` должны склеиваться через дефис перед нормализацией, иначе `normalize_grade` не распознаёт составной грейд.

## Контракты парсеров

### Динамический импорт через importlib (BUG-001)
Динамический импорт обходит реестр парсеров и захватывает лишние классы, включая `BaseParser`. Парсеры импортируются только через `PARSER_REGISTRY` из `parsers/__init__.py`.

### Grade из заголовка regex-ом (BUG-009)
Эвристика по ключевым словам заголовка даёт недостоверные результаты: `Middle` в названии может относиться к уровню продукта, не кандидата. `Grade` берётся только из фактических данных API, маппинга `experience → grade` или `GRADE_OVERRIDE_PATTERNS` в `config.py`. Regex по заголовку запрещён.

### Lead+ эвристикой из заголовка (BUG-015)
Автоматическое определение `Lead+` из заголовка давало ложные срабатывания и нарушало контракт `grade`. Источники `Lead+`: фактические данные enrichment, `grade_from_experience()` и `GRADE_OVERRIDE_PATTERNS`.

### Grade regex из свободного текста (BUG-017)
Для источников без поля `grade` (Avito) допускается только маппинг по номенклатуре заголовков внутри парсера. Извлечение `grade`, `work_format`, `experience` regex-ом из свободного текста (`meta description`, `description`) запрещено.

### company name не совпадает с таблицей companies (BUG-034)
Если `vacancy["company"]` не совпадает с `companies.name` в Supabase, фильтрация по компаниям и деактивация ломаются. Значение `vacancy["company"]` обязано совпадать с `companies.name`.

### enrich() перезаписывает description без проверки длины (BUG-044)
Контракт `enrich()`: `description` заменяется только если `len(new) > len(current)`. Остальные заполненные поля (`work_format`, `grade`, `city`) `enrich()` не трогает.

### Regex из meta description для структурированных полей (BUG-048)
Свободный текст `meta description` не является надёжным источником структурированных данных. Извлечение `grade`, `work_format`, `experience` из `meta description` или `description` regex-ом запрещено.

### content_hash включал description (BUG-055)
`description` обогащается в `enrich()` после вычисления хеша. Если включить его в хеш — изменение описания создаёт бесконечный цикл обновлений. Хеш считается из `title + grade + city + work_format + experience`. `description` в `CONTENT_HASH_FIELDS` не входит.

### HH API — 403 на все запросы без OAuth (BUG-083)
С апреля 2026 `GET /vacancies` требует application token. Токен хранится в `HH_ACCESS_TOKEN`, передаётся через `Authorization: Bearer`. Без токена парсеры получат 403.

## Supabase и PostgREST

### Метод .not_in() не существует в supabase-py (BUG-033)
Вызов `.not_in("column", list)` выбрасывает `AttributeError` в `supabase-py`. Правильная форма: `.not_.in_("column", list)`.

### Insert без upsert (BUG-046)
Конфликт по `vacancy id` — штатная ситуация гонки при параллельных прогонах. `insert` без `on_conflict` падает с ошибкой. Использовать `upsert` с `on_conflict="id"`.

### Запрос несуществующей колонки из БД (BUG-068)
Запрос несуществующей колонки вызывает ошибку PostgREST на этапе исполнения, не на этапе разработки. Перед добавлением поля в `SELECT` убедиться, что колонка существует в таблице.

## Фильтрация и ранжирование

### Фильтрация по точному совпадению строки с запятыми (BUG-020)
Поля `city` и `work_format` могут содержать несколько значений через запятую (`Москва, Санкт-Петербург`). Сравнение строки целиком всегда даёт промах. Строку нужно разбивать по запятой и матчить по каждому фрагменту отдельно.

### parser_name вместо name в фильтрах пользователя (BUG-021)
`parser_name` — идентификатор парсера, не компании. В `filters.companies` и `filters.excluded_companies` хранятся русские `name` из таблицы `companies`. Использование `parser_name` как ключа фильтра ломает блокировку и фильтрацию компаний.

### Blacklist не покрывает процессных и технических PM (BUG-071)
Regex `менеджер.{0,40}продукт` слишком широк — ловит технические и процессные роли. При расширении `TITLE_BLACKLIST_PATTERNS` проверять, не пропускает ли blacklist ложно-позитивные тайтлы (менеджер продуктовых процессов, технический PM).

### Lead+ пропускает вакансии с пустым grade при strict_mode=false (BUG-072)
Если пользователь выбрал только `Lead+`, вакансии без `grade` не релевантны независимо от `strict_mode`: `Lead+` однозначно означает руководящую позицию, а отсутствие грейда не является основанием для включения. Пустой `grade` при фильтре `Lead+` отсекается всегда.

## Telegram API

### Markdown вместо HTML (BUG-002)
Markdown в Telegram требует экранирования спецсимволов и вызывает лишние обратные слэши в тексте. Все сообщения используют `parse_mode="HTML"` с `_escape_html` и HTML-тегами.

### mark delivered без проверки результата send_message (BUG-056)
`send_message()` может вернуть `None` без исключения (403, 429). Добавлять `vacancy_id` в `sent_ids` или вызывать `mark_delivered` только если `send_message()` вернул не `None`.

### filter_saved без filter_type в properties (BUG-085)
`log_event` с `event="filter_saved"` вызывается без ключа `filter_type` в `properties`, из-за чего в аналитике `filter_type = null` у всех записей и невозможно различить тип сохранённого фильтра. Правило: каждый вызов `log_event` с `event="filter_saved"` обязан содержать в `properties` ключ `filter_type` с одним из значений: `"grades"`, `"cities"`, `"work_formats"`, `"companies"`, `"strict_mode"`, `"onboarding"`.

## Pipeline сбора вакансий

### Деактивация вакансий при ошибке парсера (BUG-058)
При ошибке одного парсера нельзя деактивировать вакансии для всех компаний — это создаёт вечно активные записи у компаний с успешным парсингом. Деактивация выполняется только для компаний с успешным парсингом через параметр `companies` в `deactivate_missing_vacancies()`.

### Scheduled delivery для пользователей с незавершённым онбордингом (BUG-084)
`get_active_users()` возвращает всех active-пользователей, включая тех, у кого `onboarding_step IS NOT NULL` (онбординг не завершён). Такие пользователи ещё не настроили фильтры и не ожидают рассылки. Правило: scheduled delivery отправляется только пользователям с `onboarding_step IS NULL`; остальные пропускаются без событий и логов уровня WARNING, счётчик `skipped_onboarding` попадает в admin report.

### Scheduled delivery не прерывает отправку при 403/429 (BUG-086)
Суть: `send_message` возвращал `None` при 403/429, цикл продолжал слать оставшиеся вакансии тому же юзеру. Правило: при первой ошибке отправки — `break` по юзеру; при 403 — деактивировать `is_active=false`.

### Нечитаемая статистика и отсутствие проблем доставки в админ-отчёте (BUG-087)
Суть: отчёт был перегружен данными по каждому парсеру, ошибки 403 от Telegram не отражались. Правило: отчёт показывает только проблемы сбора и статус доставки; 403/429 выносятся отдельными строками.

### HH_ACCESS_TOKEN отсутствует в collect.yml (BUG-088)
Суть: секрет добавлен в GitHub, но не пробрасывался в env воркфлоу. Правило: при добавлении новой env-переменной в config.py проверять `.github/workflows/collect.yml`.

## Telegram API

### Краткое название ошибки (BUG-NNN)
Суть ошибки: что именно идёт не так и при каком условии воспроизводится. Почему это плохо: какие данные портятся или какой сценарий ломается. Правило: как должен работать корректный код.

### Старый контракт 2ГИС и служебные поля Lamoda (BUG-089)
Суть: 2ГИС перенёс список с `/project/` на JSON API `/api/v1/vacancies`; Lamoda
возвращала `_raw_id`, включая карточки, для которых enrichment не вызывался.
Правило: читать все страницы нового API 2ГИС и полное описание detail; raw ID
Lamoda восстанавливать из vacancy ID, не сохранять служебные поля в карточке.

### Заголовок Контура включает город и формат (BUG-090)
Суть: текст всей ссылки карточки попадал в title и мешал распознаванию grade.
Правило: извлекать отдельный элемент заголовка; город и формат брать из отдельных
полей карточки. Enrichment не перезаписывает уже заполненный город.

### Ошибки источников скрываются за пустой выдачей и успешным workflow (BUG-091)
Суть: ДомКлик возвращал пустой список при 404, HH возвращал частичный список при
OAuth/captcha, а collector завершался с кодом 0 при ошибках парсеров.
Правило: такие ответы дают исключение, источник не считается успешно собранным;
остальные источники сохраняются, admin report отправляется, процесс получает
ненулевой exit code. Отсутствующий MTSLINK_BEARER_TOKEN отражается в отчёте.

### Устаревшие API-фильтры возвращают ложный пустой список (BUG-092)
Суть: Aviasales `specializations` возвращал [] при наличии двух Product Manager,
а МТС Линк `categoryId` больше не соответствовал текущей странице.
Правило: получать общий фирменный список, роли отбирать прежним pipeline;
публичный API МТС Линк не требует Bearer. Дату created сохранять как ISO timestamp
с реальным offset timezone, а не дописывать имя timezone к строке.

### Перенос фирменных API ДомКлика и Dodo (BUG-093)
Суть: ДомКлик перенёс API на career.domclick.ru с result/title/vacancycontent;
Dodo указывает новый backend в публичном Nuxt config и карточку через vacancyId.
Правило: ДомКлик читает все limit/offset страницы и detail по slug с Referer и
Sec-Fetch; полный description берётся из vacancycontent. Dodo получает apiURL
при запуске и использует его для list/detail; сетевую ошибку не скрывать за [].

### Успешный HH-ответ ещё не подтверждает полноту (BUG-094)
Суть: HTTP 200 с неверной формой items, повторяющимися id или списком короче found
мог считаться успешным. Правило: проверять форму, уникальность, found и лимит
выдачи 2000; неполный сбор не сохранять как успешный источник.

### Недоверенная цепочка TLS банковских источников (BUG-095)
Суть: Альфа, Т-Банк и Точка в Actions дают CERTIFICATE_VERIFY_FAILED, Chromium —
ERR_CERT_AUTHORITY_INVALID до выполнения JavaScript. Гипотеза: сайты используют
официальную российскую цепочку CA, отсутствующую в системном trust store.
Правило: сравнить цепочки и проверить API с официальными сертификатами только
для трёх source hosts; не отключать проверку HTTPS и hostname, не расширять
глобальное доверие. Подтверждение ремонта требует успешного live audit.
Actions 36911140341 подтвердил цепочку для всех трёх банков и успешные API
Альфы/Точки; у Т-Банка выявлена отдельная проблема пустого списка после 200.

### Т-Банк молча принимает устаревший запрос (BUG-096)
Суть: прежний tcareer_it_profession=product-management и вложенная pagination.it
возвращают OK с пустым списком. Актуальный DevTools POST использует
filters.generatedGraphQL и плоские limit/offset/nextPagination с totalCount.
Правило: HTTP-сбор IT/back-office по текущему контракту, без ограничения Москвой;
проверять продвижение offset, уникальность id и totalCount до city-dedup.
API base берётся из public environment.VACANCIES_PUBLIC_API. В Actions
36917545369 подтверждены все 385/385 API строк: 234 после city-dedup, 25 product.
Полное описание, как и раньше, читается обычным HTTP из HTML; «Мы предлагаем»
также включается в итоговый текст. Браузер вакансии не выгружает.

### Дублирующий аудит и слишком короткий timeout повторов (BUG-097)
Суть: два job одновременно собирали Т-Банк, а timeout enrichment 45 секунд
обрывал разрешённые повторы 429 с ожиданиями 30/60 секунд. В live-проверке
полный список получен, но восемь HTML-описаний встретили 429.
Правило: Т-Банк собирается только bank_contracts; общий audit исключает его.
Предыдущий audit ветки отменяется через concurrency. Пауза HTML GET — 5 секунд,
audit enrichment timeout — 150 секунд. DevTools POST вызывается только явным
флагом диагностического скрипта. Положительный результат требует всех описаний.

Подтверждение BUG-097: Actions 36919821912, bank_contracts успешен — 385/385
строк, все 25 описаний с четырьмя секциями, семь восстановленных 429, issues=[].

### Облачный provision меняет права платформенной роли (BUG-098)
Суть: Supabase Management SQL выполняется от postgres без superuser; ALTER
DEFAULT PRIVILEGES FOR ROLE supabase_admin запрещён, даже когда права уже
совпадают. Транзакция загрузки откатывалась. Правило: до записи сверять все
default privileges чужой роли с копией, при несовпадении останавливаться;
совпадающие платформенные ACL сохранять без ALTER. После загрузки повторно
сверять default privileges. Подтверждено загрузкой 6 таблиц и 35/53 справочников
в пустую тестовую БД; две регрессии проверяют совпадение и отказ при различии.

### Webhook читает пустое тело при HTTP chunked (BUG-099)
Суть: Vercel proxy передаёт Transfer-Encoding: chunked без Content-Length.
Прежний read(0) приводил к JSONDecodeError и 200/ok=false даже для корректного
аутентифицированного update. Правило: поддерживать обе формы HTTP тела,
проверять размеры/CRLF, не ждать EOF после последнего chunk. Три регрессии
проверяют chunks с расширением/trailer и UTF-8, обычный Content-Length,
отказ на оборванном или слишком большом теле. Live Vercel POST теперь
возвращает 200/ok=true; запрос без webhook secret — 403.


### Vercel webhook включает браузер и каждый preview копит Function Storage (BUG-100)
Суть: общий requirements включал Playwright/curl_cffi/bs4 в обе Python-функции,
а Git integration исходного проекта создавала preview при каждом push ветки
восстановления. Накопились 52 READY deployments и предупреждение 75%/10GB. Инвентарь
подтвердил 32 deployments за 2026-10-01, 28 с meta ref ветки восстановления:
пуши восстановления заметно увеличили хранение функций.
Правило: изолировать webhook requirements и payload, collector deps держать в
requirements-collector.txt; preview восстановления отключить в git.deploymentEnabled.
Очистка читает все aliases/pages, защищает current и healthy rollback, повторно
проверяет перед deletion. Удалены 28 unaliased old previews/test deployments; после двух slim test
сборок READY 52→26, 28 aliases не изменены. Dependency tree 223→39MB; actual billed storage требует
отдельной проверки и не равен простой сумме размеров установленных пакетов.

### Обрыв ответа Т-Банка останавливает весь каталог (BUG-101)
Суть: Actions 36933860419 оборвал ServerDisconnectedError посреди пагинации;
429 retry не обрабатывал разрыв соединения/недочитанное тело/timeout.
Правило: до двух повторов того же read-only getVacancies payload или HTML GET
после 5/10 секунд; offset меняется только после полного JSON. Persistent failure
выбрасывается, HTTP 5xx не маскируется; totalCount по-прежнему обязателен.
Регрессии проверяют восстановление второй страницы без потери первой и
исчерпание бюджета, отсутствие retry для 503; recovered disconnects отдельно
от recovered rate limits.

### Пустая старая группа Купера скрывает недоступность каталога (BUG-102)
Суть: устаревший group UUID возвращал 0 и считался empty success, хотя
team.kuper.ru возвращает 403 в обычном HTTP, Chrome TLS и Chromium (Actions
36935380788). Общий старый API содержит лишь одну непрофильную вакансию;
полноту это не доказывает. Правило: подтверждать доступ к карьерному сайту,
не применять obsolete group; проверять pages/ids, недоступность отдавать как
ошибку источника. Нельзя считать blocked каталог пустым, снимать вакансии или
подменять фирменный сбор HH. Тесты проверяют 403 и дубликат страницы.

### MTS/VK могут принимать неполный каталог и перезаписывать enrichment (BUG-103)
Суть: MTS при отсутствии total использовал 0 и двигал offset на запрошенный,
а не фактический размер; VK тихо завершался на next без offset или циклился
при повторной странице. VK enrich перезаписывал grade/description и извлекал
структурированный grade из meta description. Правило: проверять полный total,
уникальные ids и продвижение пагинации; grade брать только из поля «Уровень»,
заполненные поля сохранять, description менять только на более длинное.
Регрессии проверяют короткую MTS страницу, потерю/повтор/изменение total,
VK broken next/count и сохранение enrichment.

### Защита aliases устаревает между двумя удалениями Vercel (BUG-104)
Суть: helper обновлял полный inventory только один раз перед batch; новый
alias между DELETE мог не учитываться. Правило: полностью перечитывать

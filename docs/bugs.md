# Лог исправленных багов

### BUG-001: importlib вместо PARSER_REGISTRY
Файл: main.py
Было: динамический импорт через importlib находил BaseParser и падал.
Стало: используется `from parsers import PARSER_REGISTRY`.
Причина: точка входа обходила реестр парсеров и цепляла лишние классы.

### BUG-002: Markdown вместо HTML в Telegram
Файл: delivery/telegram.py
Было: сообщения отправлялись с `parse_mode="Markdown"`, в тексте появлялись лишние обратные слэши.
Стало: используется `parse_mode="HTML"`, `_escape_html` и HTML-теги.
Причина: формат сообщений не соответствовал выбранному способу рендеринга в Telegram.

### BUG-003: пустые заголовки в Avito
Файл: parsers/avito.py
Было: `card.find("a")` находил пустую ссылку-оверлей, и `title` сохранялся пустым.
Стало: используется селектор `a.vacancies-section__item-name`, заголовки извлекаются корректно.
Причина: парсер брал не тот DOM-элемент из карточки вакансии.

### BUG-004: отсутствующие грейд и опыт в Yandex
Файл: parsers/yandex.py
Было: грейд и опыт не определялись, потому что `pro_levels` не было в объекте вакансии.
Стало: грейд и опыт определялись из заголовка через `guess_grade_from_title`.
Причина: исходная реализация опиралась на поле, которого не было в выдаче списка.

### BUG-005: лишние пробелы в названиях вакансий
Файл: parsers/*.py
Было: `title` мог сохраняться с ведущими и замыкающими пробелами.
Стало: название вакансии нормализуется через `.strip()` перед сохранением.
Причина: парсеры сохраняли сырой текст без базовой очистки.

### BUG-006: затирание short_description в main.py
Файл: main.py
Было: `short_description` всегда перезаписывался результатом `generate_summary`, включая `None`.
Стало: `generate_summary` вызывается только если `short_description` отсутствует.
Причина: логика обогащения не проверяла, заполнено ли поле до генерации summary.

### BUG-007: грейды Yandex через фильтр pro_levels
Файл: parsers/yandex.py
Было: грейд и опыт определялись только из заголовка.
Стало: данные собирались отдельными запросами по `pro_levels` с дедупликацией по приоритету грейда и fallback-запросом без фильтра.
Причина: была временно выбрана неверная стратегия получения грейда из API Яндекса.

### BUG-008: Yandex pro_levels не определяет грейд вакансии

### BUG-047: снятые вакансии оставались is_active=true навсегда
Файл: main.py
Было: вакансии, исчезнувшие из API, не деактивировались и продолжали считаться активными.
Стало: после каждого прогона вакансии, отсутствующие в текущей выдаче API, переводятся в `is_active=false`.
Причина: в пайплайне не было шага синхронизации активных вакансий с актуальной выдачей источников.

## Правила и исключения

Отозваны 12 прежних положительных алиасов: в них продажи/ведение портфеля
слишком широко считались развитием бизнеса, а один presale ошибочно был PM.
Добавлены 61 точечное ограничение: компания, название и цитаты обязанностей.
Нельзя блокировать слово «клиентов» или `sales` во всём тексте.
Требования к опыту, вводная о компании и упоминание продаж в проекте сами
по себе не доказывают продажную природу.

Примеры убранных функций: Сбер/МТС «развитие малого бизнеса» — клиентские
встречи, банковские/телеком-продукты и клиентский портфель; Ozon/WB
«развитие ключевых партнёров» — seller KAM; Альфа «привлечение зарплатных
проектов» — банковские продажи; VK «директор отдела по работе с клиентами» —
план рекламной выручки и account pipeline.

Сохранены VK аккаунт-менеджер инфлюенс-маркетинга (запуск кампаний, команды,
сроки), Sber настоящий delivery клиентских проектов, МТС fixed presale
(реализация подключения, финансирование, сроки), Avito эффективность
каналов продаж (внедрение инструментов, CRM и изменения процесса),
проектные администраторы/стажёры и PM под нестандартными названиями.

Пять mixed review, потенциально подходящих:

- `mts_701411264546472252` — Big Data, ведение клиентского проекта вместе с hunting.
- `sber_4569148` — эквайринг: портфель банков-партнёров и сроки совместных проектов.
- `vk_54546` — SMB-платформы: выручка, команда и стратегические переговоры.

## Воспроизведение и применение

Полные описания, исходные семьи и решения сохранены в
`tests/fixtures/role_precision_audit.json`; цитаты guard проверяются тестом
на точное присутствие в исходном описании. Пять mixed не объявлены мусором.

```bash
python scripts/evaluate_role_precision.py --output reports/precision.json
python scripts/reselect_test_roles.py --output reports/reselection.json
python scripts/reselect_test_roles.py --output reports/reselection.json --apply
```

Последний скрипт принимает только явные TEST_* и identity @ProdRadar_bot.
По умолчанию dry run; применение атомарно и только если snapshot title/body
не изменился. Оно деактивирует снятые роли и обновляет семьи/версию/hash;
сохраняет raw metadata, обновляет source_json.selection,
не удаляет вакансии, не рассылает сообщения, не трогает пользователя, grade,
mute/pause или delivery history. У collector приоритет TEST, исходный бот
не изменён. При свежем API без достаточного описания известные рискованные
названия проходят detail enrichment до отбора; неудачный detail остаётся
review/ошибкой, а не автоматическим возвратом продаж в ленту.

Регрессы: 111 тестов — сохранённые 257, цитатные ограничения, company/title
границы, клиентские PM, rollback, live detail/no detail/cached negative,
атомарное применение без users/history и прежний product flow.

Применено к живой TEST БД:257 active с версией.6, исходные фильтры/онбординг
и24 delivery записи совпали до/после. source_json.selection обновлён вместе
с core полями без удаления native metadata. GitHub read-only проверка
[37022028000](https://github.com/Zadnessa/prodradar/actions/runs/37022028000)
загрузила19ca5d5 и прошла111 тестов (1 optional PyNaCl skipped),

Vercel rebuild не нужен: фильтры применяются collector/DB, действующий

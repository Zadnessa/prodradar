# Инструкции для AI-агентов

## Правила работы с репозиторием

- Всегда создавай новую ветку от актуального `main`.
- Не трогай файлы, которые не указаны в задаче.
- После изменений создавай PR.
- Язык комментариев в коде и коммитов — русский.

## Правила работы с документацией

- Если PR добавляет новую команду, callback-prefix, архитектурный паттерн или меняет поведение, обнови документацию в том же коммите.
- Обновляй `README.md`, если меняются команды бота или структура проекта.
- Обновляй `AGENTS.md`, если меняются правила работы агента или архитектурные паттерны.
- Обновляй `docs/context.md`, если принимается продуктовое или архитектурное решение.
- Обновляй `docs/bugs.md`, если исправляется баг: добавляй запись в конец файла по шаблону.

## Архитектурные принципы

- Список компаний, эмодзи и категории берутся из таблицы `companies` в Supabase, не хардкодить.
- Города нормализуются через таблицу `city_mappings` в Supabase, не хардкодить. Исключение: `CITY_OPTIONS` в онбординге — осознанное UX-решение.
- Один парсер = один файл в `parsers/`.
- Любой новый парсер обязательно регистрируется в `PARSER_REGISTRY` в `parsers/__init__.py`.
- Парсеры импортируются только через `PARSER_REGISTRY`, не через `importlib`.
- Ошибка одного парсера или enrichment не должна останавливать остальные.
- Telegram API вызовы идут только через `bot/telegram_api.py`, не через прямой `requests.post`.
- Telegram-сообщения используют `parse_mode="HTML"`, не Markdown.
- Пустые поля (`None`, `""`, `"Не указан"`) не показываются пользователю.
- Названия вакансий перед сохранением нормализуются через `.strip()`.
- `content_hash` определяет, нужно ли обновлять вакансию.
- `enrich()` вызывается только для новых и изменённых вакансий, до normalizer, и не должен перезаписывать уже заполненные поля.
- Деактивация снятых вакансий происходит по отсутствию `id` в текущем прогоне.
- `grade` может быть диапазоном через дефис (`Middle-Senior`); левая часть считается минимальным грейдом для фильтрации.
- Доставка вакансий — per-user через таблицу `user_vacancy_delivery`; глобальный `notified_at` устарел.
- Фильтрация находится в `delivery/filters.py`: пустой `filters` означает «показывать всё».
- `strict_mode` хранится в пользовательских фильтрах: `true` — вакансии с пустыми полями отсекаются, `false` — проходят.
- Callback prefixes: `ob:` — онбординг, `st:` — настройки, `more:` — пагинация выдачи, `hub:` — хаб returning user.

## Антипаттерны

Перед внесением изменений прочитай `docs/bugs.md` — там полный лог исправленных багов. Не повторяй их.

## Текущие ограничения и известные проблемы

- В `supabase-py` нет метода `.not_in()`: использовать `.not_.in_("column", list)`.
- `maybe_single()` на некоторых версиях Supabase может давать `406`; безопаснее делать обычный `select()` и проверять пустой список.
- Любые утверждения AI-аудитора о коде проверяй по raw GitHub URL: аудитор может видеть кэшированную или устаревшую версию файла.
